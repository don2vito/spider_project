## 1. 产品概述

### 1.1 产品名称

**XHS Data Scraper**（小红书数据采集系统）

### 1.2 产品定位

一款面向内容创作者、运营人员和数据分析师的**本地化小红书数据采集与分析工具**。通过代理服务器模式，安全合规地获取指定作者的全量笔记数据，并提供可视化的数据分析能力。

### 1.3 目标用户

| 用户角色 | 使用场景 |
|---------|---------|
| 内容创作者 | 分析竞品账号的发布策略、互动数据 |
| 运营人员 | 批量采集对标账号内容，进行竞品分析 |
| 数据分析师 | 获取结构化数据，进行深度分析 |
| 个人用户 | 备份自己发布的笔记内容（图文/视频/评论） |

### 1.4 核心价值

- **全量采集**：一键获取指定作者的全部笔记数据
- **结构化导出**：ZIP 打包下载，包含文本、图片、视频、评论
- **智能分析**：自动生成互动趋势、内容分布、发布规律等分析报告
- **本地运行**：数据不经过第三方服务器，保护隐私安全
- **一键启动**：双击 BAT 文件即可运行，无需复杂配置

### 2.2 功能模块详细说明

#### F1. 登录与会话管理

| 编号 | 功能点 | 说明 | 优先级 |
|------|--------|------|--------|
| F1.1 | Cookie 配置登录 | 用户从浏览器复制 Cookie 字符串粘贴到输入框，系统自动解析并保存 | P0 |

**Cookie 配置登录流程**：
1. 用户在 Chrome 中登录 `xiaohongshu.com`
2. F12 → Network → 复制任意请求的 Cookie 头
3. 在系统登录弹窗中粘贴 Cookie → 点击确认
4. 系统解析 Cookie，提取 `a1`、`web_session` 等关键字段
5. 更新登录状态徽章

### 3.3 API 接口清单

| 方法 | 路径 | 说明 | 请求体/参数 | 响应 |
|------|------|------|------------|------|
| GET | `/` | 提供前端页面 | - | HTML |
| GET | `/api/session/status` | 检查登录状态 | - | `{logged_in, has_a1, ...}` |
| POST | `/api/session/set` | 设置 Cookie | `{cookie_str}` | `{status, logged_in, ...}` |
| POST | `/api/login/password` | 账号密码登录 | `{phone, password}` | `{status, message}` |
| POST | `/api/search` | 搜索作者笔记 | `{user_id}` | `{notes[], user_info{}, total}` |
| GET | `/api/note/{note_id}` | 获取笔记详情 | - | 笔记详情 JSON |
| GET | `/api/note/{note_id}/comments` | 获取笔记评论 | - | `{comments[], cached}` |
| POST | `/api/download/{note_id}` | 下载单条笔记 ZIP | - | ZIP 文件流 |
| POST | `/api/download_all` | 下载全部笔记 ZIP | - | ZIP 文件流 |
| POST | `/api/analyze` | 数据分析 | - | 分析报告 JSON |
| GET | `/api/health` | 健康检查 | - | `{status, version}` |

### 3.4 反反爬策略

| 策略 | 实现方式 | 说明 |
|------|---------|------|
| X-s 签名 | xhshow 库 | 纯 Python 生成小红书 API 签名，无需浏览器环境 |
| User-Agent 轮换 | 5 个主流浏览器 UA 随机切换 | 每 20 次请求自动轮换 |
| 请求频率控制 | 随机延迟 1.5~6.5 秒 | 基于上次请求时间的动态延迟 |
| 指数退避重试 | 最多 3 次，等待 5s/15s/45s | 遇到 403/429/445/446/448 时触发 |
| 浏览器指纹模拟 | 完整请求头（Referer/Origin/Accept 等） | 模拟真实浏览器行为 |
| Cookie 自动管理 | JSON 文件持久化 | 自动加载/保存，支持手动更新 |

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 搜索响应 | 单页笔记列表 < 5 秒（受网络和频率限制影响） |
| 全量采集 | 100 条笔记 < 10 分钟（含频率控制延迟） |
| ZIP 生成 | 单条笔记 < 10 秒（不含大文件下载时间） |
| 页面加载 | 首屏 < 2 秒（本地网络） |

### 4.2 兼容性要求

| 环境 | 要求 |
|------|------|
| 操作系统 | Windows 10/11（BAT 启动），macOS/Linux（命令行启动） |
| Python | ≥ 3.10 |
| 浏览器 | Chrome 90+、Firefox 88+、Safari 14+、Edge 90+ |

### 4.3 安全要求

| 要求 | 说明 |
|------|------|
| 本地运行 | 所有数据在本地处理，不经过第三方服务器 |
| Cookie 安全 | Cookie 仅保存在本地文件，不对外传输 |
| 无数据库 | 使用内存存储，关闭服务器后数据自动清除 |

## 7. 已知限制与风险

| 限制 | 说明 | 应对方案 |
|------|------|---------|
| 签名算法更新 | 小红书可能更新 X-s 签名算法 | 依赖 xhshow 库更新，需定期 pip install --upgrade xhshow |
| API 接口变更 | 小红书非官方 API 可能随时变更 | 关注 xhshow 社区动态，及时适配 |
| 频率限制 | 大量采集可能触发 IP 封禁 | 已内置频率控制和退避策略 |
| 登录验证码 | 账号密码登录可能触发验证码 | 建议优先使用 Cookie 方式 |
| 图片/视频有效期 | 小红书图片 URL 带鉴权，有效期短 | 下载时即时转存到 ZIP |
| 合规风险 | 大规模爬取可能违反平台用户协议 | 建议仅用于个人数据分析，控制采集频率 |
