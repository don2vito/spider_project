# 小红书数据爬虫 — 技术实现手册

> 基于最新版本代码梳理，涵盖反爬对抗、API 分析、数据结构、核心流程。

---

## 一、整体架构

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  index.html │────▶│  FastAPI     │────▶│  Playwright │
│  (前端UI)   │◀────│  server.py   │◀────│  Chromium   │
└─────────────┘     └──────────────┘     └──────┬──────┘
                           │                     │
                    ┌──────┴──────┐        ┌─────┴──────┐
                    │ DataStore  │        │  XHS 网页   │
                    │ ZIPExporter│        │  SSR + API  │
                    │ Analyzer   │        └────────────┘
                    └─────────────┘
```

**核心策略**：不直接调用 XHS API（避免签名/TLS 指纹问题），而是通过 Playwright 启动真实 Chromium 浏览器，让 XHS 前端 JS 自行生成合法签名，然后从 SSR 渲染数据和拦截的 API 响应中提取数据。

## 二、XHS 反爬手段与对应反反爬技术

### 2.1 XHS 反爬手段一览

| 序号 | 反爬手段 | 说明 |
|------|----------|------|
| 1 | **X-s 签名验证** | API 请求需携带 `X-s`、`X-t`、`X-s-common` 等签名头，由前端 JS 动态生成 |
| 2 | **TLS 指纹检测** | 检测 JA3/JA4 指纹，非浏览器客户端（httpx/requests）直接被拒绝（HTTP 406） |
| 3 | **签名算法升级** | 2026年3月起，旧版 XYS_ 格式签名完全失效，仅接受 XYW_ 格式 |
| 4 | **xsec_token 机制** | 笔记详情页必须携带 `xsec_token` 参数，否则返回 404（error_code=300031） |
| 5 | **验证码拦截** | 检测到自动化行为时，重定向到 `/website-login/captcha?verifyType=124` |
| 6 | **SSR 渲染** | 页面数据嵌入 `window.__INITIAL_STATE__`，不再通过独立 AJAX API 加载 |
| 7 | **Vue 3 Reactive Proxy** | SSR 数据为 Vue 3 响应式代理对象，含循环引用，无法直接 `JSON.stringify()` |
| 8 | **非法 JSON 值** | SSR 数据中包含 `undefined`、`NaN`、`Infinity` 等非法 JSON 值 |
| 9 | **请求频率限制** | 短时间大量请求会触发验证码或 IP 封禁 |
| 10 | **webdriver 检测** | 检测 `navigator.webdriver` 属性判断是否为自动化浏览器 |

### 2.2 对应反反爬技术

#### 2.2.1 绕过签名 + TLS 指纹：Playwright 真实浏览器

```python
# 不使用 httpx/requests 直接调用 API
# 改用 Playwright 启动真实 Chromium，让 XHS 前端 JS 自行处理签名
browser = await playwright.chromium.launch(
    headless=True,
    args=[
        "--disable-blink-features=AutomationControlled",  # 禁用自动化标志
        "--no-sandbox",
        "--disable-dev-shm-usage",
    ]
)
```

**原理**：Playwright 使用真实 Chromium 内核，TLS 握手产生的指纹与普通浏览器一致，XHS 前端 JS 正常执行签名逻辑。

#### 2.2.2 浏览器指纹伪装（9项反检测措施）

通过 `add_init_script` 在每个页面加载前注入：

| 措施 | 代码 | 对抗的反爬 |
|------|------|-----------|
| 隐藏 webdriver 标志 | `Object.defineProperty(navigator, 'webdriver', {get: () => undefined})` | 自动化检测 |
| 模拟浏览器插件 | 覆写 `navigator.plugins`，注入 Chrome PDF Plugin 等3个插件 | 插件指纹检测 |
| 模拟语言列表 | `navigator.languages = ['zh-CN', 'zh', 'en']` | 语言指纹 |
| 模拟操作系统 | `navigator.platform = 'Win32'` | 平台指纹 |
| 模拟 CPU 核心数 | `navigator.hardwareConcurrency = 8` | 硬件指纹 |
| 模拟设备内存 | `navigator.deviceMemory = 8` | 硬件指纹 |
| 覆写权限查询 | `permissions.query` 对 notifications 返回真实状态 | 权限指纹 |
| 模拟 Chrome 对象 | `window.chrome = {runtime: {}, loadTimes, csi}` | Chrome 特征检测 |
| 删除自动化属性 | `delete window.cdc_adoQpoasnfa76pfcZLmcfl_*` | ChromeDriver 残留特征 |

#### 2.2.3 xsec_token 机制利用

```
# 笔记详情页 URL 必须携带 xsec_token，否则返回 404
https://www.xiaohongshu.com/explore/{note_id}?xsec_token={token}&xsec_source=pc_user
```

**xsecToken 来源**：嵌入在每个 noteCard 对象中（列表页 SSR 数据），无需额外获取。

#### 2.2.4 验证码自动检测与处理

```
检测到验证码 URL (/website-login/captcha?verifyType=...)
    │
    ├─ headless 模式 → 自动切换为有头模式（显示浏览器窗口）
    │                   用户手动解决验证码
    │                   解决后自动继续
    │
    └─ headed 模式 → 等待用户解决（每2秒轮询，最长120秒）
```

**关键区分**：`/404?source=/404/sec_xxx` 不是验证码，而是"笔记暂时无法浏览"（error_code=300031），不应触发验证码处理流程。

#### 2.2.5 SSR 数据提取（绕过 Vue 3 Proxy）

XHS 的 `window.__INITIAL_STATE__` 是 Vue 3 响应式代理对象，存在循环引用（dep→computed），无法在浏览器中 `JSON.stringify()`。

**解决方案**：从 HTML 源码中的 `<script>` 标签提取原始文本，在 Python 端解析。

```python
# Step 1: 在浏览器中提取 <script> 标签的文本内容
scripts = await page.evaluate("""
    () => Array.from(document.querySelectorAll('script'))
        .filter(s => s.textContent.includes('__INITIAL_STATE__'))
        .map(s => s.textContent)
""")

# Step 2: 在 Python 中用正则解析 JSON
# 格式1: window.__INITIAL_STATE__=JSON.parse("...")
match = re.search(r'__INITIAL_STATE__\s*=\s*JSON\.parse\("(.+?)"\)', script_text)

# 格式2: window.__INITIAL_STATE__={...}
# 使用花括号深度计数找到 JSON 结尾
```

#### 2.2.6 智能 JSON 清理（状态机）

SSR 数据中包含 `undefined`、`NaN`、`Infinity` 等非法 JSON 值，简单 `str.replace()` 会误替换字符串内容中的这些值。

**解决方案**：字符级状态机，跟踪 `in_string` 和 `escape_next` 状态：

```python
def _clean_json_string(json_str):
    result = []
    in_string = False
    escape_next = False
    i = 0
    while i < len(json_str):
        ch = json_str[i]
        if escape_next:
            result.append(ch); i += 1; escape_next = False; continue
        if ch == '\\' and in_string:
            result.append(ch); i += 1; escape_next = True; continue
        if ch == '"':
            in_string = not in_string
        if in_string:
            result.append(ch); i += 1; continue
        # 仅在字符串外部替换
        if json_str[i:i+9] == 'undefined':
            result.append('null'); i += 9; continue
        if json_str[i:i+3] == 'NaN':
            result.append('0'); i += 3; continue
        if json_str[i:i+8] == 'Infinity':
            result.append('0'); i += 8; continue
        result.append(ch); i += 1
    return ''.join(result)
```

#### 2.2.7 请求频率控制

| 场景 | 间隔时间 | 说明 |
|------|----------|------|
| 笔记详情页抓取 | 1.5秒 | enrichment 阶段 |
| 失败后重试 | 2秒 | 增加等待 |
| 连续失败熔断 | 前3个全部失败则停止 | 避免触发封禁 |
| 评论页滚动 | 2秒/次 | 最多滚动10次 |

## 四、数据获取核心流程

### 4.1 搜索用户笔记（完整流程）

```
用户输入 user_id
    │
    ▼
[Step 1] 获取用户信息
    │  导航到 /user/profile/{user_id}
    │  SSR 提取 userPageData（nickname、fans、follows）
    │
    ▼
[Step 2] 获取笔记列表
    │  导航到 /user/profile/{user_id}
    │  SSR 提取 user.notes 二维网格 → noteCard 列表
    │  滚动加载 + API 拦截获取更多笔记
    │  DOM 提取作为后备
    │
    ▼
[Step 3] 逐个丰富笔记详情（Enrichment）
    │  遍历每个 noteCard
    │  用 noteCard.xsecToken 构造详情页 URL
    │  导航到 /explore/{noteId}?xsec_token=...&xsec_source=pc_user
    │  SSR 提取 noteDetailMap[noteId].note
    │  合并 desc、time、imageList、video、tagList、完整 interactInfo
    │  每次间隔 1.5 秒，连续失败则熔断
    │
    ▼
[Step 4] 格式化输出给前端
```

### 4.2 获取笔记评论

```
构造带 xsec_token 的 URL
    │
    ▼
[Step 1] 注册 API 响应监听器（在导航前！）
    │  匹配 URL 包含 "/comment/" 的响应
    │  域名：edith.xiaohongshu.com 或 edith.xhscdn.com
    │
    ▼
[Step 2] 导航到笔记详情页
    │  页面加载时自动触发评论 API 请求
    │  监听器捕获 API 响应
    │
    ▼
[Step 3] 从 SSR 提取评论
    │  路径1: noteDetailMap[noteId].comments.list
    │  路径2: note.commentData.comments（旧版）
    │
    ▼
[Step 4] 滚动加载更多评论
    │  最多滚动 10 次，每次间隔 2 秒
    │  新加载的评论通过 API 监听器捕获
    │
    ▼
[Step 5] 合并去重（SSR + API）
```

**关键点**：API 监听器必须在导航前注册，否则会错过页面加载时的评论 API 响应。

### 4.3 三级数据提取后备

```
SSR 提取（主要）
    │  从 <script> 标签中解析 window.__INITIAL_STATE__
    │  成功率最高，数据最完整
    │
    ├─ 失败 ▼
API 拦截（辅助）
    │  监听 edith.xiaohongshu.com 的 API 响应
    │  需要页面滚动触发加载
    │
    ├─ 失败 ▼
DOM 提取（后备）
       从渲染后的 HTML 元素中提取
       CSS 选择器：section.note-item, a[href*="/explore/"]
       仅能获取 noteId 和标题
```

## 五、API 接口分析

### 5.1 已知 API 端点

| 端点 | 方法 | 用途 | 触发方式 |
|------|------|------|----------|
| `/api/sns/web/v1/login/qrcode/create` | POST | 创建登录二维码 | 主动调用 |
| `/api/sns/web/v1/login/qrcode/status` | GET | 轮询二维码扫描状态 | 主动调用 |

### 5.2 API 请求头

XHS API 请求需要以下关键头部（由前端 JS 自动生成）：

```
X-s: XYW_xxxx...           # 签名（XYW_ 格式，2026年3月后）
X-t: 1715000000000         # 时间戳
X-s-common: xxx            # 公共签名参数
Content-Type: application/json
Origin: https://www.xiaohongshu.com
Referer: https://www.xiaohongshu.com/
```

## 八、已知限制与注意事项

1. **xsec_token 时效性**：`xsecToken` 有时效限制，过期后需重新从列表页获取
2. **评论 API 监听时序**：必须在页面导航前注册监听器，否则会错过首次加载的评论
3. **URL 反引号前缀**：SSR 数据中的 URL 可能以反引号 `` ` `` 开头，需去除
4. **interactions 字段类型不确定**：可能是 dict 也可能是 list，代码中做了兼容处理
5. **SSR 数据中的非法 JSON**：`undefined`、`NaN`、`Infinity` 需要智能清理
6. **验证码与404区分**：`/404/sec_xxx` 是内容限制，不是验证码
7. **enrichment 性能**：17篇笔记约需 25-30 秒（每篇 1.5 秒间隔）
8. **分页限制**：当前仅获取第一页 SSR 数据（约17篇），滚动加载可获取更多
