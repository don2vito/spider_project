## 一、整体架构

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  index.html │────▶│  FastAPI     │────▶│  Playwright │
│  (前端UI)   │◀────│  server.py   │◀────│  Chromium   │
└─────────────┘     └──────────────┘     └──────┬──────┘
                           │                     │
                    ┌──────┴──────┐        ┌─────┴──────┐
                    │ DataStore  │        │  XHS 网页   │
                    │ ZIPExporter│        │  SSR + API  │
                    │ Analyzer   │        └────────────┘
                    └─────────────┘
```

**核心策略**：不直接调用 XHS API（避免签名/TLS 指纹问题），而是通过 Playwright 启动真实 Chromium 浏览器，让 XHS 前端 JS 自行生成合法签名，然后从 SSR 渲染数据和拦截的 API 响应中提取数据。

**技术栈**：

| 组件 | 技术 | 用途 |
|------|------|------|
| 后端框架 | FastAPI (uvicorn) | HTTP 服务、路由 |
| 浏览器自动化 | Playwright (async) | 启动 Chromium、页面导航、API 拦截 |
| HTTP 客户端 | httpx | 图片/视频下载、Cookie 管理 |
| 数据分析 | pandas | DataFrame 构建、统计分析 |
| 文件导出 | zipfile + BytesIO | ZIP 打包（内存中生成，不落盘） |
| 前端 | 原生 HTML/CSS/JS | 单页面 UI |

## 二、XHS 反爬手段与对应反反爬技术

### 2.1 XHS 反爬手段一览

| 序号 | 反爬手段 | 说明 | 严重程度 |
|------|----------|------|----------|
| 1 | **X-s 签名验证** | API 请求需携带 `X-s`、`X-t`、`X-s-common` 等签名头，由前端 JS 动态生成 | 🔴 致命 |
| 2 | **TLS 指纹检测** | 检测 JA3/JA4 指纹，非浏览器客户端（httpx/requests）直接被拒绝（HTTP 406） | 🔴 致命 |
| 3 | **签名算法升级** | 2026年3月起，旧版 `XYS_` 格式签名完全失效，仅接受 `XYW_` 格式 | 🔴 致命 |
| 4 | **xsec_token 机制** | 笔记详情页必须携带 `xsec_token` 参数，否则返回 404（error_code=300031） | 🟠 严重 |
| 5 | **验证码拦截** | 检测到自动化行为时，重定向到 `/website-login/captcha?verifyType=124` | 🟠 严重 |
| 6 | **SSR 渲染** | 页面数据嵌入 `window.__INITIAL_STATE__`，不再通过独立 AJAX API 加载 | 🟡 中等 |
| 7 | **Vue 3 Reactive Proxy** | SSR 数据为 Vue 3 响应式代理对象，含循环引用（dep→computed），无法直接 `JSON.stringify()` | 🟡 中等 |
| 8 | **非法 JSON 值** | SSR 数据中包含 `undefined`、`NaN`、`Infinity` 等非法 JSON 值 | 🟡 中等 |
| 9 | **请求频率限制** | 短时间大量请求会触发验证码或 IP 封禁 | 🟠 严重 |
| 10 | **webdriver 检测** | 检测 `navigator.webdriver` 属性判断是否为自动化浏览器 | 🟡 中等 |
| 11 | **评论数据隐藏** | 评论不在 SSR 顶层，嵌套在 `noteDetailMap[noteId].comments.list` 中 | 🟡 中等 |
| 12 | **视频地址保护** | 视频地址需从 `video.media.stream` 或 `video.consumer.originVideoKey` 中提取 | 🟡 中等 |
| 13 | **URL 反引号前缀** | SSR 数据中的 URL 以反引号 `` ` `` 开头（如 `` `https://... ``），需去除 | 🟢 轻微 |
| 14 | **interactions 类型不确定** | `userPageData.interactions` 可能是 dict 也可能是 list | 🟢 轻微 |
| 15 | **Content-Disposition 编码** | 中文文件名在 HTTP 头中需 URL 编码（RFC 5987） | 🟢 轻微 |

#### 2.2.5 SSR 数据提取（绕过 Vue 3 Proxy）

XHS 的 `window.__INITIAL_STATE__` 是 Vue 3 响应式代理对象，存在循环引用（dep→computed），无法在浏览器中 `JSON.stringify()`。

**解决方案**：从 HTML 源码中的 `<script>` 标签提取原始文本，在 Python 端解析。

```python
# Step 1: 在浏览器中提取 <script> 标签的文本内容
script_contents = await page.evaluate("""
    () => {
        const scripts = document.querySelectorAll('script');
        const results = [];
        for (const s of scripts) {
            const text = s.textContent || '';
            if (text.includes('__INITIAL_STATE__')) {
                results.push(text);
            }
        }
        return results;
    }
""")

# Step 2: 在 Python 中用正则解析 JSON
# 格式1: window.__INITIAL_STATE__=JSON.parse("...")
match = re.search(r'__INITIAL_STATE__\s*=\s*JSON\.parse\("(.+?)"\)', script_text, re.DOTALL)

# 格式2: window.__INITIAL_STATE__={...}
# 使用花括号深度计数找到 JSON 结尾
```

**两种解析方法**：

| 方法 | 匹配模式 | 处理方式 |
|------|----------|----------|
| JSON.parse 方法 | `__INITIAL_STATE__=JSON.parse("...")` | 提取引号内字符串，反转义后 `json.loads()` |
| 直接对象方法 | `__INITIAL_STATE__={...}` | 花括号深度计数找到 JSON 结尾，`_clean_json_string()` 后 `json.loads()` |

**花括号深度计数算法**（处理嵌套 JSON）：

```python
if json_str.startswith('{'):
    depth = 0
    in_string = False
    escape_next = False
    for i, ch in enumerate(json_str):
        if escape_next: escape_next = False; continue
        if ch == '\\' and in_string: escape_next = True; continue
        if ch == '"': in_string = not in_string; continue
        if in_string: continue
        if ch == '{': depth += 1
        elif ch == '}':
            depth -= 1
            if depth == 0: end_idx = i + 1; break
```

#### 2.2.6 智能 JSON 清理（字符级状态机）

SSR 数据中包含 `undefined`、`NaN`、`Infinity` 等非法 JSON 值，简单 `str.replace()` 会误替换字符串内容中的这些值。

**解决方案**：字符级状态机，跟踪 `in_string` 和 `escape_next` 状态：

```python
def _clean_json_string(json_str: str) -> str:
    """仅在字符串外部替换非法 JSON 值"""
    result = []
    in_string = False
    escape_next = False
    i = 0
    while i < len(json_str):
        ch = json_str[i]
        if escape_next:
            result.append(ch); i += 1; escape_next = False; continue
        if ch == '\\' and in_string:
            result.append(ch); i += 1; escape_next = True; continue
        if ch == '"':
            in_string = not in_string
        if in_string:
            result.append(ch); i += 1; continue
        # 仅在字符串外部替换
        if json_str[i:i+9] == 'undefined':
            result.append('null'); i += 9; continue
        if json_str[i:i+3] == 'NaN':
            result.append('0'); i += 3; continue
        if json_str[i:i+8] == 'Infinity':
            result.append('0'); i += 8; continue
        result.append(ch); i += 1
    return ''.join(result)
```

**替换规则**：

| 非法值 | 替换为 | 说明 |
|--------|--------|------|
| `undefined` | `null` | JavaScript undefined → JSON null |
| `NaN` | `0` | JavaScript NaN → 数值 0 |
| `Infinity` | `0` | JavaScript Infinity → 数值 0 |

#### 2.2.7 评论获取：监听器时序控制

**关键问题**：评论 API 在页面加载时就触发，如果先导航再设置监听器，会错过评论响应。

**解决方案**：先注册 API 监听器，再导航页面。

```python

    if "/comment/" in response.url and "edith.xiaohongshu.com" in response.url:
        body = await response.json()
        # 提取评论...

page.on("response", on_response)

# Step 2: 再导航到页面（API 响应会被捕获）
ssr_data = await self._extract_ssr_data(note_url)

# Step 3: 滚动加载更多评论
for _ in range(10):
    await page.evaluate("window.scrollTo(0, document.body.scrollHeight)")
    await page.wait_for_timeout(2000)
```

**评论数据来源优先级**：

| 优先级 | 来源 | 路径 | 说明 |

| 1 | SSR | `noteDetailMap[noteId].comments.list` | 页面加载时嵌入 |

#### 2.2.11 Content-Disposition 中文编码

### 3.6 视频数据结构

XHS 视频笔记的 `video` 对象包含多种视频 URL 来源，按优先级排列：

```
note.video = {
    // 路径1: 多码率视频流（最高优先级）
    "media": {
        "stream": {
            "h264": [                          // H.264 编码
                {
                    "videoBitrate": 2000000,   // 比特率（也用于选最高分辨率）
                    "height": 1080,             // 视频高度
                    "masterUrl": "https://...",  // 主 URL
                    "backupUrls": [             // 备用 URL（更可靠）
                        "https://...",
                        "https://...",
                    ],
                }
            ],
            "h265": [                          // H.265 编码（同结构）
                {
                    "videoBitrate": 3000000,
                    "height": 1080,
                    "masterUrl": "https://...",
                    "backupUrls": [...],
                }
            ]
        }
    },
    // 路径2: 原始视频 key
    "consumer": {
        "originVideoKey": "xxx",               // 拼接: http://sns-video-bd.xhscdn.com/{key}
    },
    // 路径3: 直接视频 key（备选）
    "originVideoKey": "xxx",
}
```

**视频 URL 提取策略**（`get_video_url` 方法）：

| 优先级 | 路径 | 选择逻辑 |
|--------|------|----------|
| 1 | `video.media.stream.h265[].backupUrls[0]` | 选最高分辨率的 H.265 流 |
| 2 | `video.media.stream.h264[].backupUrls[0]` | H.264 备选 |
| 3 | `video.media.stream.*[].masterUrl` | 无 backupUrls 时使用 |
| 4 | `video.consumer.originVideoKey` | 拼接 CDN URL |
| 5 | `video.originVideoKey` | 直接 key 拼接 |

**提取算法**：

```python
def get_video_url(self, note: dict) -> str:
    video = note.get("video") or {}
    media = video.get("media") or {}
    stream = media.get("stream") or {}

    best_url = ""
    best_height = 0
    for codec in ["h265", "h264"]:
        for s in stream.get(codec, []):
            height = s.get("videoBitrate", 0) or s.get("height", 0) or 0
            urls = s.get("backupUrls") or []
            url = urls[0] if urls else s.get("masterUrl", "")
            if url and height >= best_height:
                best_url = url
                best_height = height

    if best_url:
        return best_url
    # Fallback: originVideoKey
    key = video.get("consumer", {}).get("originVideoKey") or video.get("originVideoKey")
    return f"http://sns-video-bd.xhscdn.com/{key}" if key else ""
```

## 四、数据获取核心流程

### 4.1 搜索用户笔记（完整流程）

```
用户输入 user_id
    │
    ▼
[Step 1] 获取用户信息（get_user_info）
    │  导航到 /user/profile/{user_id}
    │  SSR 提取 user.userPageData（nickname、fans、follows）
    │  失败不阻塞（non-critical）
    │
    ▼
[Step 2] 获取笔记列表（get_user_notes）
    │  导航到 /user/profile/{user_id}
    │  SSR 提取 user.notes 二维网格 → noteCard 列表
    │  注册 API 监听器 → 滚动加载更多笔记
    │  DOM 提取作为后备（CSS: section.note-item, a[href*="/explore/"]）
    │
    ▼
[Step 3] 逐个丰富笔记详情（Enrichment）
    │  遍历每个 noteCard（跳过已有 desc 的）
    │  用 noteCard.xsecToken 构造详情页 URL
    │  导航到 /explore/{noteId}?xsec_token=...&xsec_source=pc_user
    │  SSR 提取 noteDetailMap[noteId].note
    │  合并字段：desc、time、imageList、video、tagList、完整 interactInfo
    │  每次间隔 1.5 秒
    │  连续失败熔断：前3个全部失败则停止
    │
    ▼
[Step 4] 格式化输出给前端
    │  note_url 带上 xsec_token 参数
    │  cover_url 从 cover.infoList 提取（去除反引号前缀）
    │  返回 enriched/data_warning 字段
```

def _guess_ext(url: str, data: bytes) -> str:
    # URL 关键字匹配
    if "png" in url: return ".png"
    if "gif" in url: return ".gif"
    if "webp" in url: return ".webp"
    # Magic bytes 匹配
    if data[:4] == b'\x89PNG': return ".png"

    if data[:4] == b'RIFF': return ".webp"

## 九、已知限制与注意事项

1. **xsec_token 时效性**：`xsecToken` 有时效限制，过期后需重新从列表页获取
2. **评论 API 监听时序**：必须在页面导航前注册监听器，否则会错过首次加载的评论
3. **URL 反引号前缀**：SSR 数据中的 URL 可能以反引号 `` ` `` 开头，需去除
4. **interactions 字段类型不确定**：可能是 dict 也可能是 list，代码中做了兼容处理
5. **SSR 数据中的非法 JSON**：`undefined`、`NaN`、`Infinity` 需要智能清理（字符级状态机）
6. **验证码与404区分**：`/404/sec_xxx` 是内容限制，不是验证码；只有 `/website-login/captcha?verifyType=...` 才是验证码
7. **enrichment 性能**：17篇笔记约需 25-30 秒（每篇 1.5 秒间隔）
8. **分页限制**：当前仅获取第一页 SSR 数据（约17篇），滚动加载可获取更多
9. **视频下载大小校验**：下载后校验 > 1KB，避免下载到错误内容
10. **视频超时设置**：视频文件较大，下载超时设为 120 秒
11. **视频流选择**：优先选择 H.265 最高分辨率，备选 H.264
12. **评论递归解析**：子评论（subComments）支持多层嵌套，递归解析
13. **数据分析容错**：所有互动数据为 0 时，engagement_rate 计算需特殊处理（除零保护）
14. **浏览器状态恢复**：页面丢失时自动重新初始化浏览器（`_ensure_ready` 方法）
15. **headless → headed 切换**：检测到验证码时自动从无头模式切换为有头模式，需关闭旧浏览器再重新启动
16. **Content-Disposition 编码**：中文文件名使用 `filename*=UTF-8''` 格式（RFC 5987）
17. **内存 ZIP 生成**：所有 ZIP 文件在内存中生成（BytesIO），不落盘，适合流式响应
