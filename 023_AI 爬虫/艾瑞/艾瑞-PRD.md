# 艾瑞咨询研究报告爬虫系统 - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品背景
艾瑞咨询是中国领先的新经济行业研究机构，其官网发布了大量高质量的行业研究报告。用户需要一个自动化工具来批量获取这些报告的元数据和 PDF 文件。

### 1.2 产品目标
开发一个集爬虫、代理服务器和前端展示于一体的应用系统，实现：
- 全量爬取艾瑞咨询研究报告数据
- 提供可视化界面展示报告列表
- 支持单个和批量 PDF 下载
- 一键启动，开箱即用

### 1.3 目标用户
- 行业研究人员
- 市场分析师
- 投资从业者
- 学术研究者

## 2. 功能需求

### 2.1 核心功能

#### 2.1.1 三层爬取引擎
| 层级 | 名称 | 优先级 | 描述 |
|-----|------|-------|------|
| L1 | API 接口层 | P0 | 直接调用网站 API 获取 JSON 数据 |
| L2 | HTML 解析层 | P1 | 使用 BeautifulSoup 解析服务端渲染的 HTML |
| L3 | Browser Use 层 | P2 | 使用 Playwright 控制浏览器兜底 |

#### 2.1.2 数据爬取
- **全量爬取**：能够获取所有历史报告数据
- **增量更新**：支持从上次位置继续爬取
- **数据去重**：基于报告 ID 自动去重
- **断点续传**：支持中断后从断点继续

#### 2.1.3 数据展示
- **报告列表**：表格形式展示所有报告
- **封面预览**：显示报告封面图片
- **搜索功能**：支持按报告标题关键词搜索，实时过滤结果
- **行业筛选**：支持按行业分类筛选（消费者洞察、医疗健康、人工智能等）
- **时间筛选**：支持按发布时间范围筛选（最近一周、一月、一年、自定义范围）
- **排序功能**：支持多字段排序（发布时间、浏览量、标题等）
- **组合筛选**：支持搜索 + 行业 + 时间的组合筛选条件

#### 2.1.4 下载管理
- **单个下载**：点击按钮下载单个报告 PDF
- **批量下载**：选择多个报告批量下载
- **全量下载**：一键下载所有报告
- **下载进度**：显示当前下载进度
- **文件名规范**：使用报告标题作为文件名

### 2.2 辅助功能

#### 2.2.1 系统功能
- **一键启动**：双击 bat 文件启动整个系统
- **自动更新**：定时检查新报告
- **数据导出**：导出为 Excel/CSV
- **日志记录**：记录操作日志和错误信息

#### 2.2.2 用户认证
- **手机号登录**：支持手机号 + 验证码登录方式
- **登录状态保持**：登录状态保存在 localStorage，7天自动过期
- **权限控制**：登录后可下载报告，未登录仅可浏览
- **验证码获取**：点击获取验证码，60秒倒计时防刷
- **退出登录**：支持手动退出清除登录状态

#### 2.2.3 用户界面
- **响应式设计**：适配桌面和移动端
- **暗黑模式**：支持亮色/暗色主题
- **多语言**：支持中文/英文切换

## 3. 非功能需求

### 3.1 性能需求
- **爬取速度**：单条数据获取 < 2s
- **并发数**：详情页请求最多 5 并发
- **页面加载**：首屏加载 < 3s
- **列表渲染**：支持 1000+ 条数据流畅滚动

### 3.2 可靠性需求
- **可用性**：系统可用率 > 99%
- **容错性**：单点失败不影响整体流程
- **数据完整性**：确保数据不丢失、不重复
- **降级策略**：API 失效自动降级到 HTML 解析

### 3.3 安全需求
- **请求频率**：控制请求频率，避免被封禁
- **User-Agent**：模拟真实浏览器请求头
- **数据保护**：本地存储，不上传云端
- **访问控制**：本地运行，无需登录

### 3.4 兼容性需求
- **操作系统**：Windows 10/11
- **浏览器**：Chrome, Edge, Firefox, Safari
- **Python**：3.8+
- **网络**：支持代理配置

interface Report {

### 5.2 交互流程

#### 5.2.1 首次使用流程
```
1. 用户双击 start.bat
2. 系统自动安装依赖
3. 启动 Python 服务器
4. 打开浏览器访问 http://localhost:5000
5. 前端自动触发首次爬取
6. 显示爬取进度
7. 爬取完成后展示报告列表
```

#### 5.2.2 日常使用流程
```
1. 用户打开浏览器访问 http://localhost:5000
2. 系统加载本地缓存数据
3. 用户浏览报告列表
4. 用户点击"更新数据"检查新报告
5. 用户选择报告并下载
```

#### 5.2.3 下载流程
```
单个下载：
1. 用户点击某行"下载"按钮
2. 前端发送请求到 /api/download/{id}
3. 后端获取 PDF 链接并下载
4. 保存到 downloads/ 目录
5. 返回下载成功状态
6. 前端更新下载状态

批量下载：
1. 用户勾选多个报告
2. 点击"批量下载"按钮
3. 前端发送 POST /api/download/batch
4. 后端创建下载队列
5. 逐个下载并返回进度
6. 可选打包为 ZIP
```

## 6. API 接口规范

### 6.1 后端 API

#### GET /api/crawl
触发全量爬取任务

**Response:**
```json
{
  "success": true,
  "message": "Crawl task started",
  "taskId": "task_123456"
}
```

#### GET /api/crawl/status
获取爬取任务状态

**Response:**
```json
{
  "status": "running",
  "progress": 45,
  "total": 1000,
  "current": 450,
  "message": "Crawling page 10..."
}
```

#### GET /api/reports
获取报告列表

**Query Parameters:**
- `page`: 页码 (默认 1)
- `pageSize`: 每页数量 (默认 20)
- `search`: 搜索关键词
- `industry`: 行业筛选
- `sortBy`: 排序字段
- `sortOrder`: 排序方向 (asc/desc)

**Response:**
```json
{
  "success": true,
  "data": {
    "list": [...],
    "total": 1500,
    "page": 1,
    "pageSize": 20
  }
}
```

#### GET /api/download/{id}
下载单个报告 PDF

**Response:**
- Content-Type: application/pdf
- Content-Disposition: attachment; filename="xxx.pdf"

#### POST /api/download/batch
批量下载报告

**Request Body:**
```json
{
  "ids": ["freport.4822", "freport.4821"]
}
```

**Response:**
```json
{
  "success": true,
  "taskId": "download_123",
  "message": "Batch download started"
}
```

### 6.2 错误码

| 错误码 | 描述 | 处理建议 |
|-------|------|---------|
| 200 | 成功 | - |
| 400 | 请求参数错误 | 检查请求参数 |
| 404 | 报告不存在 | 刷新数据重试 |
| 429 | 请求过于频繁 | 稍后重试 |
| 500 | 服务器内部错误 | 查看日志 |
| 503 | 服务暂不可用 | 检查网络连接 |
